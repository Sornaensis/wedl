## Meaning of parity

Functional parity means comparable supported authored data, temporal queries,
character views, editing and author/reader workflows. It includes capabilities
that are optional upstream, such as semantic/hybrid retrieval. Raw inspection of
an unsupported record does not count as its implemented semantics.

The rewrite need not reproduce old source formats, exact wire shapes, internal
module structure, cache architecture or transaction machinery. Migration and
compatibility work are excluded, as requested. Safe reviewed publication outcomes
and browser editing remain functional requirements even if their implementation
is smaller. Historical benchmark targets and release infrastructure are outside
this estimate. Every Rust project version remains v1 until the plan is complete.

## Explicit reveal and reader workflow

Reveal plans now use the shared private `wedl-author/v1` source, exact committed
and current author reads, bounded validation and guarded saves. A plan binds one
work and ordered occurrence milestones. Record, section and exact-text admissions
accumulate in authored work order, independently of segment reuse or story placement.
Plan notes and labels remain private. Pinned retcon graphs exclude reveal plans;
the native graph likewise adds no invented reveal dependency edges.

Pure projection enforces trusted identity/revision/plan/scope and ordinary
owner, audience, perspective and temporal admission. Scope includes the title
visibility gate. Corrections are filtered before suppression, and suppression
precedes reveal matching. A section-only admission never supplies owner prose or
siblings. Ordinary public body projection covers the seven supported body kinds,
with event, scene/conversation and environment time gates. Description sections
retain independent exact validity.

The separate reader service loads only authenticated original Git source under an
explicit trusted installed policy. Without policy, or for a publication/revision/
ceiling mismatch, it refuses before source lookup. Public and author-simulation
installations are distinct; simulation intersects installed author permissions
and uses an explicit story time/text policy. Replacing or revoking even an equal
installation invalidates in-flight work at emission. Original commit/tree/blob
and repository identity checks remain independent of dirty live source.

Search, counts and pages derive only from minimal admitted items. Full default
Unicode casefold supplies search and heading normalization. HMAC-SHA256 cursors
bind repository, original source blobs, policy generation, scope/principal, mode,
query, page size, occurrence, story time, text policy, ceiling and admitted dataset.
Complete source, admitted-unit and Markdown bounds precede search; complete
selected JSON bounds precede pagination.
Reader output contains no private source metadata, work/plan labels, segment prose,
hidden counts or grant input. Its separate loopback origin mounts only its client
and page/search routes; no author router, session or policy installation route is
present. CLI and both browser surfaces use the same native projection.

Native adaptations are explicit: literal 40/64-character Git object IDs replace
upstream cache identity; cursors are 72 lowercase hex characters; this native
server binds only to loopback; Markdown is displayed as inert text. Private heading
restrictions carry through descendants until a nearer explicit audience mapping
overrides them. Pure character projection retains native learned-owner/description
admission and excludes raw body prose. The public and author-simulation service
uses the public/ordinary author-as-of lens. Source works may exceed 1,024 occurrences,
while the bounded reader service refuses those works rather than truncating them.

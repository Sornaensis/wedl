Core native YAML field guide
          
The existing typed editor and Actions Plans accept environment, relationship, story-point and hypothesis records, alongside the other supported kinds. Use exact record IDs and include kind in each closed YAML patch. Collection fields replace the complete collection.

          
Common fields include status, domain, threads, section_audiences, audience and perspectives. World fields include timelines, default_timeline, capabilities, threads and relationship_metrics, alongside existing world declarations.

          
Objects accept object_affordances as a literal string array. Order, repeated values, empty strings and an explicit empty array are preserved. An omitted field leaves its existing value unchanged. Events accept related_story_points. Story points retain explicit lifecycle, requires, when and manual or suggest policy; authoring does not activate them automatically.

          
Hypotheses provides create, adopt and reject previews using this same native Plan format. Possibilities stay author-only and noncanonical.
